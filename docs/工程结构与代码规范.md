# 工程结构与代码规范

本文档约束这个项目后续如何继续长大，避免“功能越做越多，目录越来越乱”。

## 目标

整理后的仓库遵循下面几条原则：

1. 源码、运行产物、文档、协议样本分层清楚。
2. 前端模板、样式、脚本不再和 Python 业务逻辑混写。
3. 启动、测试、依赖、编辑器规范在仓库根目录统一可见。
4. 新功能默认先放到合适模块，而不是直接堆到根目录。

## 根目录分工

- `services/`
  核心 Python 服务层，按领域拆分模块。

- `scripts/`
  启动、benchmark、运维辅助脚本。

- `tests/`
  单元测试与测试夹具，禁止混入运行时输出。

- `docs/`
  项目级规划、方案、路线图和规范文档。

- `contracts/`
  真实协议合约样本与 Solidity 目标。

- `research/`
  历史攻击案例与研究语料。

- `data/schema/`
  结构化 schema 定义，属于源码资产。

- `artifacts/`、`data/db/`
  运行时产物目录，不纳入版本管理。

## 服务层分工

- `services/analysis/`
  合约接入、分类、静态分析、深语义分析、审计报告生成。

- `services/research/`
  研究问题生成、引用整理、实验计划、备忘录、论文草稿。

- `services/monitoring/`
  链上扫描、持续索引、签名解析、监控任务。

- `services/storage/`
  工件归档、数据库后端、索引状态持久化。

- `services/api/`
  HTTP 接口、页面渲染、前端模板和静态资源。

- `services/shared/`
  项目级配置、共享模型与跨模块通用对象。

## AI 增强层组织规范

AI 相关能力必须遵守“基础分析先行，LLM 只做增强”的原则：

- `services/shared/llm_client.py`
  放通用的 LLM 客户端抽象，不把模型调用散落到业务代码里。

- `services/research/llm_research_enhancer.py`
  放研究模块的 LLM 提示词、结果解析和安全合并逻辑。

约束：

1. LLM 不能替代本地证据采集、静态分析和语义分析。
2. LLM 输出必须可回退，配置缺失时系统仍可完整运行。
3. LLM 输出必须引用本地已知 evidence / citation 标识，不能无约束扩写。
4. 页面必须显式展示当前结果是否经过 AI 增强。

## 前端组织规范

前端相关文件统一收敛到 `services/api/` 下：

- `services/api/web_ui.py`
  只负责把数据装配成页面片段，不再内嵌整页 CSS / JS。

- `services/api/templates/`
  页面壳子与静态 HTML 模板。

- `services/api/static/`
  CSS 和浏览器脚本。

- `services/api/server.py`
  路由分发和静态资源输出。

这样做的好处是：

1. Python 逻辑和前端资源职责分离。
2. 后续想替换模板或样式时，不用翻 1000 多行 Python 文件。
3. 页面问题可以直接定位到模板、样式或脚本，而不是混在一起查。

## 命名与文件放置规则

1. 新的项目级文档放 `docs/`，不要散落到仓库根目录。
2. 新的运行时缓存、临时目录一律放到已定义的运行目录，并写入 `.gitignore`。
3. 新的测试文件放 `tests/unit/`，命名保持 `test_*.py`。
4. 新的脚本放 `scripts/`，并保证可以直接从仓库根目录运行。
5. 新的静态前端文件只放 `services/api/static/` 或 `services/api/templates/`。

## 代码风格要求

1. Python 统一使用 4 空格缩进。
2. JS / CSS / HTML 统一使用 2 空格缩进。
3. 注释尽量简短，但涉及关键流程、关键判断时必须写中文注释。
4. 服务端函数优先做单一职责，不把“路由 + 业务 + 展示 + 序列化”写在一个函数里。
5. 页面渲染必须对动态文本做转义，避免把原始内容直接拼进 HTML。

## 工程元信息

仓库根目录统一维护以下文件：

- `pyproject.toml`
  项目元数据和工具配置。

- `.editorconfig`
  基础缩进、换行、编码规范。

- `Makefile`
  统一测试、启动、benchmark、lint 命令入口。

- `requirements-dev.txt`
  开发环境依赖清单。

## 验收标准

工程整理完成后，至少满足：

1. 首页可正常访问，CSS/JS 通过静态资源路由加载。
2. `web_ui.py` 不再包含整页内联 CSS/JS。
3. 根目录具备 `pyproject.toml`、`.editorconfig`、`Makefile`。
4. `.gitignore` 不再使用粗暴的 `*.json` 全局忽略。
5. 单元测试通过，启动脚本可正常运行。
