## 文档分工原则

- `项目目标`
  描述项目目标、背景、边界与终态。

- `当前不足与能力缺口`
  描述当前现状、问题、风险与不足。

- `系统方案设计`
  描述系统设计、架构方案、技术决策与模块划分。

- `实施路线图`
  描述开发顺序、里程碑、交付物、评测与执行计划。

- `审计效果提升方案与验收标准`
  专门描述审计结果应该如何提升、应达到什么样的交付质量，以及如何逐项验收。

- `工程结构与代码规范`
  描述仓库目录边界、前端资源组织、根目录工程配置和新增文件放置规则。

## 维护约定

- 新的项目级规划文档优先放在 `docs/` 下。
- 除非是运行入口或工程配置，不在仓库根目录新增规划类 Markdown 文件。
- 如果后续文档变多，可进一步拆分为：
  `docs/architecture/`、`docs/roadmap/`、`docs/research/`、`docs/operations/`。
